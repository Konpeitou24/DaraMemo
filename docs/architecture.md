# アーキテクチャ概要（DaraMemo）
DaraMemo は、ユーザーの作業時間・AFK（離席）時間・休憩時間を記録・送信するためのデスクトップ向けアプリケーションです。

このアプリケーションは、**Python を用いたバックエンドと、WPF によるフロントエンドを分離した構成**を採用しており、下記のようなモジュールアーキテクチャを持ちます。

---

## 📦 全体構成
```
DaraMemo/
├── backend/                    # Python製バックエンド（ロジック＋API）
│   ├── app/                    # AFK検知ロジック（常駐処理）
│   ├── api/                    # Flask REST API（UIと連携）
│   ├── shared/                 # ロジック/API 共通の定義・ツール
│   └── main.py                 # アプリ起動エントリポイント
│
├── frontend/                   # C# + WPF UI（通知・トグルなど）
│   ├── DaraMemo/               # WPF アプリ本体
│   └── DaraMemo.sln            # ソリューション定義
│
├── debug.ps1                   # 仮想環境を有効化して main.py を起動
├── build.ps1                   # Nuitka による exe ビルドスクリプト
└── requirements.txt            # Python依存ライブラリ一覧

```
---

## 🔍モジュール別の責務

### `main.py`（= アプリケーションエントリポイント）

- **Runtimeクラス**を起動し、常駐プロセスを開始します。
- Python側の全体初期化を担います。
- WPF との通信は Flask API 経由で行われます。

---

### `app/` （AFK監視ロジック層）

- ユーザーのキーボード・マウス操作を監視し、AFK状態を検知します。
- `keyboard_activity_detector.py` や `runtime.py` により、非アクティブ状態を判定しログとして記録します
---

### `api/` （REST API層）

- WPF からの「休憩モード開始／終了」などのリクエストを受け付ける軽量 API 層です。
- `Flask` を用いて、ローカルホスト上での通信を提供します。
- AFK 監視とはプロセス分離されており、独立して動作します。

---

### `shared/`（共通ユーティリティ層）

複数のモジュール（`app/` と `api/`）から共通して利用される機能を一元管理します。

- `constants/`：アプリ内で利用される定数（アプリ名やAFKしきい値など）
- `db/`：PostgreSQL への保存・取得ロジック
- `models/`：AFKログなどのデータ構造（DTO/Entity）
- `utils/`：通知（トースト）や非同期処理ユーティリティ

>本層により、API層・常駐監視層のコードが重複せず、保守性が高まります。

---

##  🔌 通信構成（内部）

```
[WPF UI] ⇄ REST API（localhost:5000）⇄ Flask（api/）
                               ↓
                       PostgreSQL（DB）
```

- UIのトグル操作などは Flask API に送られ、共有ロジックを通じて処理されます。
- AFKログは、作業終了時に直接 PostgreSQL に保存されます。

## ✅ 採用技術と設計思想

| 項目 | 内容 |
|:---|:---|
| **バックエンド** | Python + Flask + 常駐監視 (pynput) |
| **フロントエンド** | WPF (C#) + REST API クライアント |
| **データ保存** | PostgreSQL (外部DB。Flask経由または直アクセス) |
| **ビルド** | Nuitkaにより`.exe`化。`build.ps1`により自動処理 |
| **実行方式** | `main.py`をPowerShellスクリプト経由で起動 |
| **プロセス構成** | Flask APIとAFK監視はプロセス分離。マルチプロセス起動を許容 |
| **コード共通化** | `shared/`に共通定数・DBアクセス・通知・データモデルなどを集約 |

## 用語解説

- **AFK (Away From Keyboard)**
  > ユーザーが操作を行っていない状態の略称です。本アプリでは、これを一定時間（例：300秒）継続すると「さぼり」として記録します。

- **REST API**
  > HTTP 通信を用いて外部から操作命令や情報取得を行うためのインターフェースです。WPF UI と Python バックエンドはこの形式で連携します。

- **PostgreSQL**
  > 高性能なリレーショナルデータベース。AFK ログや作業時間などの永続化に使用されます。

- **ユーティリティ (utils)**
  > 通知・タイマーなど、複数箇所から共通して使われる便利な関数群です。

- **マルチプロセス設計**
  > Flask APIとAFK監視を別プロセスで動かす設計により、UIの操作中でもバックグラウンド処理が安定して継続できます。
