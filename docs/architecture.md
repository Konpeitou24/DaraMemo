# アーキテクチャ概要：DaraMemo（サボりログ自動記録システム）

## 概要

**DaraMemo** は、*ユーザーの「さぼり状態」* を自動検知し、記録する**ローカル完結型**のシステムです。

- 一定時間の無操作を検知すると、WPFアプリがトースト通知を行います。
- バックエンドは業務ロジック・データ記録を担当し、通信は REST API 経由で行います。



## システム構成

### フロントエンド

- **実装**: `C#` + `WPF`
- **役割**:
  - UI表示
  - トースト通知
  - ユーザー操作の検知
  - バックエンドへのリクエスト送信

### バックエンド

- **実装**: `Python` + `Flask`
- **役割**:
  - 業務ロジック
  - さぼり状態の状態管理
  - DBアクセス
  - APIの提供

### データベースサーバー

- **役割**: 永続化されたログ情報の保存のみを担当（他の処理は行わない）

### 通信

- ローカルPC内で、フロントエンドとバックエンドが `localhost` を通じて REST API で通信
---

## 採用技術

| コンポーネント   | 技術                            |
|------------------|-------------------------------------|
| フロントエンド   | `C#`, `WPF`（トースト通知機能含む）   |
| バックエンド     | `Python`, `Flask`                   |
| データベース     | 任意（例：`SQLite`, `PostgreSQL`）   |
| 通信             | `REST API`（`localhost`）           |

---

## アーキテクチャパターン分類

### クライアント-サーバーアーキテクチャ

- フロントエンド（クライアント）とバックエンド（サーバー）を**明確に分離**。


### ローカル分離型アーキテクチャ（疑似マイクロサービス）

- ローカル内でプロセスを分けて疎結合に設計。REST API によって通信する構成。


### 3層アーキテクチャに近い構成

| 層名               | コンポーネント       |
|--------------------|----------------------|
| プレゼンテーション層 | `WPF`               |
| アプリケーション層   | `Flask`　　　　　　　|
| データ層            | `DB`　　　　　　|

---

## 補足事項

- システムはローカル完結型であり、インターネット接続は不要です。
- WPFのトースト通知により、Slackなど外部サービスへの依存を排除しています。
- 各コンポーネントは疎結合で構成されているため、テスト・保守が容易です。
