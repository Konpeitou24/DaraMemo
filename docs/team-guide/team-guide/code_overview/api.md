# `api/` フォルダー

## api.py

Flask アプリを非同期で起動・停止する `Api` クラスを定義しています。AFK監視アプリケーションと並行してAPIを動作させるため、サーバーを別スレッドで管理しています。

### 主な構成

- **routes**  
  エンドポイントのURLと関数のペアを登録するリスト。  
  例：`("/start-break", handler_function)`

- **__init__()**  
  Flaskアプリとサーバー周りの初期化処理を行います。

### サーバー制御関数

- **run()**  
  WSGIサーバーを生成し、スレッドでバックグラウンド起動します。

- **_serve_loop()**  
  サーバースレッド内で1リクエストずつ処理します。`shutdown()`が呼ばれるまでループ。

- **shutdown()**  
  スレッドに停止指示を出し、確実に終了させます。

### 用語解説

- **Flask**  
  Pythonでよく使われるWebアプリケーションフレームワーク。APIやWeb画面を作るのに使われる。

- **WSGIサーバー**  
  Flaskアプリを動かすための標準的な仕組み。`make_server()` を使ってHTTP通信を処理する。

- **スレッド**  
  プログラムの処理を分けて同時に進める方法。APIを裏で動かしながら他の処理も並行して行える。

- **非同期**  
  複数の処理を同時に動かすこと。ここでは「APIを待っている間にも別の作業ができる」という意味。

- **イベントフラグ（`threading.Event`）**  
  処理の「やる／やめる」などの合図を送るための仕組み。`shutdown()`で使われている。

## __init__.py

このファイルは、Python に「このフォルダはパッケージ（モジュールの集まり）ですよ」と伝えるための印です。

ファイルの中身は空でも問題ありません。

> ※以降の `__init__.py` ファイルも基本的には同じ役割を果たすため、個別の解説は省略します。

**用語解説**
---

- **パッケージ**  
  Pythonで複数のファイルやフォルダをまとめて扱う仕組みです。たとえば `shared.utils.non_blocking_timer` のように階層的にimportできるのは、パッケージ構造のおかげです。

- **`__init__.py`**  
  このファイルがあると、そのフォルダは「パッケージ」として認識され、他のファイルから `import` できるようになります。Python 3.3以降ではなくても動く場合がありますが、明示的に置くのが安全で推奨されます。


## routes/break_routes.py

`break_routes.py` は、休憩関連のAPI（例：休憩開始、休憩終了など）をまとめるためのファイルです。Flaskの `Blueprint` 機能を使って、APIのルート定義をジャンルごとに分けやすくしています。

この構成によって、APIが増えたときでも見通しよく管理できます。

### 現在の構成

- `bp = Blueprint("break_routes", __name__)`  
  → Blueprintインスタンスの生成だけを行っています。
- エンドポイントはまだ定義されていません。
- `api.py` から `register_blueprint(bp)` を使ってアプリに組み込まれる想定です。

### 将来的な使い方（例）

```python
@bp.route("/start-break", methods=["POST"])
def start_break():
    # 休憩開始の処理
    ...
```

### この構成の意図

- APIを「休憩」「ユーザー」「セッション」など、責務ごとに分離する
- ルーティングが肥大化しにくく、レビューや機能追加がしやすくなる
- 初学者にも「このファイルには何を書くべきか」が明確になる

### 用語解説

- **Blueprint（ブループリント）**  
  FlaskでAPIのルート（URLと処理の対応）を複数のファイルに分けて整理するための仕組みです。  
  たとえば、ユーザー関連のAPIは `user_routes.py`、休憩関連は `break_routes.py` に書く、というふうに「種類ごとに分けて管理できる」ようになります。  
  大きなアプリケーションを作るとき、1ファイルにすべてのルートを書くと見づらくなるので、Blueprintで整理するのが一般的です。

- **ルート（エンドポイント）**  
  APIを呼び出すときの「URLパス」のことです。たとえば、クライアントが `/start-break` にPOSTリクエストを送ると、対応する関数が呼び出されます。  
  Flaskでは `@bp.route("/start-break", methods=["POST"])` のようにルートを定義します。

- **`__name__`（ダブルアンダースコア ネーム）**  
  Pythonにあらかじめ用意されている特別な変数です。  
  今のファイルが「直接実行されたスクリプトかどうか」や、「Blueprintの登録に必要なモジュール名」として使われます。Blueprintでは、内部的にファイルの位置を把握するためにこれを使います。

- **`@bp.route()`**  
  Flaskで「このURLが呼ばれたら、この関数を実行する」と設定するための記述です。  
  デコレータ（関数の上に `@` でつける特殊な文法）を使って、URLと処理関数を結びつけます。

- **`register_blueprint()`**  
  Flaskアプリに Blueprint を追加するための関数です。  
  たとえば `app.register_blueprint(break_bp)` のように書くことで、`break_routes.py` で定義されたルートを Flaskアプリに組み込みます。  
  これを呼び出さないと、ルートが登録されず、アクセスできません。
