# shared

このディレクトリは、アプリケーション内の複数の層（AFK監視・API層など）で共通して利用される部品（定数・ユーティリティ・DB・モデル定義など）を集約しています。  
責務が共有されるものをここに配置することで、構造が明確になり、再利用性・保守性が高まります。

---

## constants/app_resources.py

このファイルには、アプリケーション内で使用する定数（リソース）を管理するための `AppResources` クラスが定義されています。

`Enum`（列挙型）を使うことで、定数の使い回しやミス防止、リファクタビリティの向上が期待できます。

---

### 主な構成

- **AppResources（Enumクラス）**  
  アプリケーションのタイトルやAFK判定のしきい値（秒）など、変更頻度の少ない値をまとめて定義しています。  
  `Enum` を継承することで、コード補完や誤入力の防止にもつながります。

- **TITLE**  
  アプリケーションのタイトルです。UI上のラベルやウィンドウタイトルなどに使用されます。  
  値は `"DaraMemo"`。

- **AFK_THRESHOLD**  
  ユーザーがマウスやキーボードを操作しなかった場合に「AFK（離席）」と判断される時間（秒数）です。  
  値は `300`（＝5分）に設定されています。

---

### 用語解説

- **Enum（列挙型）**  
  あらかじめ決まった選択肢の中から値を選ぶときに使うクラスです。  
  定数に意味を持たせて名前付きで管理でき、バグを減らせます。  
  例：`AppResources.TITLE.value` として `"DaraMemo"` を取得できます。

- **AFK（Away From Keyboard）**  
  ユーザーが操作をせずに離席している状態を意味します。  
  この値がAFK判定の基準時間として使われます。

## db/afk_repository.py

このファイルは、AFK関連のデータをデータベースに保存・取得するためのリポジトリ層を担う予定です。

現在は未実装ですが、以下のような責務が想定されています：

### 将来的な役割（予定）

- **AFKデータの永続化**  
  AFK（離席）・作業・休憩時間のログを PostgreSQL に保存するためのインターフェースを提供する予定です。

- **データベースアクセスの集約**  
  SQL実行やトランザクション処理など、FlaskやAFK監視ロジックと分離して担当させる設計です。

### 補足

- **リポジトリパターン**  
  アプリケーションとデータベースアクセスを疎結合に保つための設計手法です。将来的にデータ構造が変わっても、影響を限定的にできます。

- **PostgreSQL**  
  本プロジェクトで採用しているリレーショナルデータベースです。SQLでの操作が前提です。

## models/afk_log.py

このファイルは、AFKログ（作業時間・離席時間・休憩時間など）をアプリケーション内で表現するためのデータモデルクラスを定義する予定のモジュールです。

現在は未実装ですが、今後以下のような情報を表現するクラスを定義する予定です。


### 将来的な役割（予定）

- **AFKログのデータ構造定義**  
  ・ユーザーID  
  ・作業開始時刻・終了時刻  
  ・作業時間／離席時間／休憩時間（いずれも秒）  
  などを**1件の記録（レコード）**として表します。

- **DTO（Data Transfer Object）やDB保存用オブジェクトとしての活用**  
  APIやDBとのデータのやりとりの際に、このモデルを使うことで情報の整合性を保ちます。

### 用語解説

- **データモデル**  
  プログラム内で「どんな情報を・どの形式で」扱うかを決めたクラスのことです。  
  例えば「ユーザーの名前と年齢を持つUserクラス」などが典型例です。

- **レコード**  
  データベースやログなどで使う用語で、「1件分の情報の集まり」です。  
  例：1人のユーザーが、いつ作業を始めて、どれだけ作業して、どれだけ休憩したかの記録1件。

- **DTO（Data Transfer Object）**  
  データをAPIなどで送受信するときに使う、「転送専用のデータ構造」です。  
  DB保存用クラスよりも軽量で、画面に出すときなどにちょうどいい形にする目的で使われます。

- **AFKログ**  
  ユーザーが「何時から何時まで作業したか」「どれだけ離席したか」「どのくらい休憩したか」などを記録したもの。  
  DaraMemoの記録対象の中心的なデータです。

## utils/non_blocking_timer.py

このファイルは、**一定間隔ごとに非同期で処理（コールバック関数）を呼び出すためのタイマー機能**を提供します。  
特定の時間間隔での定期処理（ログ記録や監視処理など）をブロッキングなしに実現できるため、他の処理と並行して安全に動かすことができます。

---

### 主な構成

- **NonBlockingTimer クラス**  
  非同期スレッドで動作する定期タイマー。任意の関数（または複数の関数）を指定間隔ごとに実行できます。

- **__init__()**
  - `interval`：タイマーの実行間隔（秒単位）。0 以下の値は `ValueError`。
  - `callback`：コールバック関数、またはそのリスト。定期的に呼び出される処理。

- **start()**
  - タイマーを開始します。内部でスレッドを起動し、一定間隔ごとに処理を実行。

- **stop()**
  - タイマーを停止します。必要に応じてスレッドの終了を待ちます。

- **_main_loop()**
  - 実行中フラグが立っている間、一定時間スリープ → コールバック呼び出しを繰り返します。

- **_run_callbacks()**
  - 登録されたすべてのコールバック関数を個別スレッドで安全に実行します。

---

### 用語解説

- **コールバック関数**  
  あらかじめ登録しておき、特定の条件やタイミングで自動的に呼び出される関数のことです。  
  他の関数の引数として渡すことが多く、処理が完了したときやイベントが発生したときに実行されます。  
  非同期処理やイベント駆動型のプログラミングで広く利用されます。

- **非ブロッキング**  
  ある処理が完了するのを待たずに、他の処理を並行して実行できる仕組みです。  
  プログラム全体の停止（ブロッキング）を回避し、応答性や実行効率を高めるために使われます。  
  Pythonでは、スレッドや非同期処理（`asyncio`）などによって非ブロッキングが実現できます。

- **スレッド**  
  プログラムの中で、複数の処理を同時に実行するための軽量な処理単位です。  
  時間のかかる処理をメインの流れと並行して動かすことで、アプリケーションの応答性を維持できます。  
  Pythonでは `threading` モジュールを使ってスレッドを作成・制御します。

- **daemon（デーモン）スレッド**  
  メインスレッド（アプリケーションの本体）が終了すると、それに伴って自動的に停止するように設定されたスレッドのことです。  
  主にバックグラウンドで動作し、明示的に終了処理を行わなくてもよいような補助的な処理に使われます。  
  Pythonでは `threading.Thread` の `daemon=True` という設定で指定できます。

- **overload（オーバーロード）**  
  Pythonの型ヒント機能において、同じ関数名でも異なる引数の組み合わせ（シグネチャ）を定義できるようにする仕組みです。  
  実行時には1つの実体関数のみが存在しますが、`@overload` を使うことで開発時に型補完や型チェックの精度を高めることができます。  
  `typing.overload` デコレータを使って記述します。

## utils/interval.py

このファイルは、アプリケーション内で使用するさまざまな「時間間隔（インターバル）」を簡単かつ統一的に扱うためのユーティリティを提供しています。

時間を「秒（float型）」に正規化して返すことで、内部処理の一貫性を保ちつつ、可読性と利便性を高めています。

---

### 主な構成

- **IntervalUnit（Enum）**  
  分・秒・ミリ秒・時間といった単位を定義した列挙型です。主にバリデーション用のログ出力などに使われます。

- **Interval（ユーティリティクラス）**  
  任意の単位で与えた時間値を「秒（float）」に変換する静的メソッド群を提供します。  
  `from_minutes()`、`from_seconds()`、`from_milliseconds()`、`from_hours()` の4つの変換メソッドがあります。

- **定数（ONE_SECONDなど）**  
  よく使うインターバルを定数として定義し、再利用性・可読性を高めています。すべて `秒単位` のfloat値です。

---

### 利用例（※参考：実装コードでは使用しません）

```python
from shared.utils.interval import Interval

Interval.ONE_SECOND      # 1.0
Interval.from_minutes(2) # 120.0
```

---

### 用語解説

- **インターバル（Interval）**  
  処理の繰り返し間隔や、一定時間待機するための「時間の長さ」のことを指します。本モジュールでは、すべて秒（float型）で統一して管理します。

- **Enum（列挙型）**  
  限られた選択肢（定数）を名前付きで定義するクラスです。  
  ここでは、時間の単位（秒、分、ミリ秒、時間）を表すために使われています。コードの安全性や保守性を高める目的があります。

- **静的メソッド（@staticmethod）**  
  クラスのインスタンスを生成せずに呼び出せるメソッドのことです。  
  クラスの状態を必要としない補助的な処理に使われます。ここでは `Interval.from_seconds()` などが該当します。

- **バリデーション（検証処理）**  
  関数やメソッドに渡された値が、想定された条件を満たしているかをチェックする処理です。  
  このモジュールでは、負の時間値を許可しないために `_validate_input()` メソッドでチェックしています。

- **ロギング（logging）**  
  アプリケーションの実行中に発生した出来事（エラー・警告・情報など）を記録する仕組みです。  
  本ファイルでは、不正な値を検出した際に警告ログを出力しています。

## utils/notifier.py

このファイルは、**ユーザーに通知（トーストメッセージ）を表示するためのユーティリティクラス**を定義しています。  
作業開始や休憩終了など、アプリケーションからのフィードバックを視覚的に伝える手段として使用されます。

---

### 主な構成

- **Notifier クラス**  
  通知（トースト）を表示する役割を持つクラスです。`plyer` ライブラリを通じて OS ネイティブの通知機能を呼び出します。

- **title（プロパティ）**  
  通知に表示されるタイトルです。インスタンス生成時に渡された値がこのプロパティに保存されます。

- **run_toast() メソッド**  
  実際にトースト通知を表示するメソッドです。メッセージ内容と表示時間（秒）を引数として受け取ります。

---

### 使われている外部モジュール・値

- **`plyer.notification`**  
  クロスプラットフォームでトースト通知を表示するためのライブラリです。  
  Windows / macOS / Linux で同様のコードが動作します。

- **`AppResources.TITLE.value`**  
  アプリケーションの名前として表示される定数値です。`shared/constants/app_resources.py` で定義されています。

---

### 用語解説

- **トースト通知（Toast Notification）**  
  画面の一部に数秒間だけ表示される小さなポップアップ通知のことです。ユーザーの操作を妨げず、情報を伝えるのに向いています。

- **通知（Notification）**  
  アプリケーションがユーザーに何かを伝える仕組みの総称です。トースト通知はその一種です。

- **`plyer` ライブラリ**  
  Pythonからデスクトップ通知やバッテリーステータスの取得などを、**クロスプラットフォーム**で扱える便利なライブラリです。内部では OS に応じた仕組みを呼び出しています。

- **プロパティ（Property）**  
  クラスの中で値を保持する変数のことです。ここでは `title` が該当します。

- **timeout（タイムアウト）**  
  通知が画面上に表示される時間（秒数）を指定するための値です。`plyer` では一部のOSで無視される場合もありますが、目安として設定されます。
